# 실습 자원 정리

지금까지 실습에서 생성한 자원을 아래 순서대로 정리합니다.

> **정리 범위**
> - 본인 계정이 속한 실습 프로젝트에서 이번 과정에 사용한 자원만 선택합니다.
> - File Storage, MySQL 인스턴스 그룹, 서브넷과 VPC도 정리합니다. 필요한 데이터는 삭제 전에 별도로 보관합니다.
> - 자원 이름은 실습에서 사용한 예시입니다. 실제 생성한 이름과 연결 관계를 확인합니다.
> - 테스트 계정의 역할 회수와 계정 삭제는 진행하지 않습니다.
> - 삭제 확인 창에 표시된 대상을 확인하고, 창에서 요구하는 확인 문구를 입력합니다. 영상에서는 `영구 삭제`를 입력합니다.
> - 연결된 자원을 먼저 정리해야 다음 자원을 삭제할 수 있습니다. 처리 중인 항목은 삭제 완료를 확인한 뒤 진행합니다.

## 1. 알림 정책

1. Alert Center > 알림 정책으로 이동합니다.
2. 실습에서 만든 CPU 부하 정책과 인스턴스 재시작 정책을 차례로 선택해 삭제합니다.
3. 삭제 확인 창에서 정책 이름을 확인하고 `영구 삭제`를 입력한 뒤 삭제합니다.
4. 실습 정책이 목록에서 사라졌는지 확인합니다. 서버 정리에 앞서 정책을 삭제하면 정리 중 불필요한 알림이 발생하는 것을 막을 수 있습니다.

## 2. 수신 채널

1. Alert Center > 수신 채널로 이동합니다.
2. 실습에서 만든 `alert` 채널을 선택해 삭제합니다.
3. 확인 창에 `영구 삭제`를 입력하고 실행한 뒤 목록을 확인합니다.

## 3. DNS

1. DNS에서 실습에 사용한 영역을 엽니다.
2. 로드밸런서의 퍼블릭 IP로 연결한 A 레코드를 선택해 삭제합니다.
3. 이번 실습 전용으로 만든 DNS 영역을 삭제합니다.

## 4. 고가용성 그룹

1. Load Balancing > 고가용성 그룹으로 이동합니다.
2. 실습에서 만든 `App_HA` 그룹을 선택해 삭제합니다.
3. 확인 창에서 이름을 확인하고 `영구 삭제`를 입력한 뒤 실행합니다.
4. 목록에서 삭제 결과를 확인합니다.

## 5. 대상 그룹 B

1. 대상 그룹 `App_Target_B`의 더보기 메뉴에서 리스너 연결 설정을 엽니다.
2. 연결된 리스너의 선택을 해제하고 저장합니다.
3. 연결이 해제된 뒤 대상 그룹을 삭제합니다.
4. 확인 창의 이름을 확인하고 `영구 삭제`를 입력해 실행합니다.

## 6. 대상 그룹 A

1. `App_Target_A`도 리스너 연결 설정에서 연결을 해제하고 저장합니다.
2. 연결 해제가 반영되면 대상 그룹을 삭제합니다.
3. 두 실습 대상 그룹이 목록에 남아 있지 않은지 확인합니다.

## 7. 로드밸런서

1. 로드밸런서 목록에서 `App_LB_A`와 `App_LB_B`를 선택합니다.
2. 삭제 확인 창의 대상 이름을 확인하고 `영구 삭제`를 입력해 삭제합니다.
3. 두 로드밸런서가 목록에서 사라졌는지 확인합니다. 퍼블릭 IP는 이후 별도로 정리합니다.

## 8. 파일 스토리지

1. File Storage > Basic에서 실습에 사용한 `fs-01`을 선택합니다.
2. 필요한 파일을 보관했는지 확인하고 삭제합니다.
3. 파일 시스템에 저장된 데이터도 함께 삭제됩니다. 처리 결과를 확인합니다.

## 9. 데이터베이스

1. MySQL > 인스턴스 그룹에서 실습용 `database`를 선택합니다.
2. 더보기 > 삭제를 선택하고 `영구 삭제`를 입력합니다.
3. Primary와 Standby를 포함한 인스턴스 그룹의 삭제 결과를 확인합니다.

## 10. 서버

1. Beyond Compute Service > Virtual Machine > 인스턴스로 이동합니다.
2. 실습에서 사용한 웹 서버, 두 번째 VPC의 서버, 배스천을 확인하고 선택합니다.
3. 서버 접속이 필요한 작업을 모두 마친 뒤 더보기 > 삭제를 선택합니다.
4. 대상 목록을 확인하고 `영구 삭제`를 입력해 실행합니다.
5. 목록에서 삭제 결과를 확인합니다. 정지와 달리 삭제한 서버는 같은 상태로 다시 시작할 수 없습니다.

## 11. 버킷

1. Object Storage에서 실습 버킷을 확인합니다.
2. 객체가 남아 있으면 먼저 삭제해 빈 버킷으로 만듭니다.
3. Lab11에서 만든 `bucket-test` 등 남아 있는 실습 버킷을 삭제합니다.
4. 목록에서 삭제 결과를 확인합니다.

## 12. 트랜짓 연결

1. Transit Gateway > Attachment 목록을 엽니다.
2. `vpc_1`과 `vpc_2`에 연결된 실습 어태치먼트를 차례로 삭제합니다.
3. 이름이 비어 있으면 연결된 VPC와 식별자로 대상을 구분합니다.
4. 두 연결의 삭제 완료를 확인합니다.

## 13. 트랜짓 게이트웨이

1. Transit Gateway 목록으로 돌아갑니다.
2. 연결 수가 0개인 것을 확인하고 실습용 `transit`을 삭제합니다.
3. 게이트웨이와 해당 기본 라우팅 테이블의 정리 결과를 확인합니다.

## 14. 퍼블릭 IP

1. VPC > 퍼블릭 IP로 이동합니다.
2. 삭제한 서버와 로드밸런서에서 연결 해제된 실습 주소를 확인합니다.
3. 해당 주소를 선택해 삭제하고 목록을 확인합니다.
4. 서버 삭제 후에도 퍼블릭 IP가 남을 수 있으므로 별도로 확인합니다.

## 15. 보안 그룹

1. 실습 자원에 연결된 네트워크 인터페이스가 남아 있지 않은지 확인합니다.
2. VPC > 보안 그룹에서 웹 서버, MySQL, 배스천용 실습 보안 그룹을 삭제합니다.
3. 기본 보안 그룹은 유지합니다.
4. 기본 그룹의 인바운드 규칙에서 실습 중 추가한 ICMP 규칙 두 개만 제거합니다.
5. 프로토콜과 출발지를 확인하고 원래 있던 규칙은 유지한 채 저장합니다.

## 16. 서브넷

1. 서브넷 목록에서 두 VPC의 실습 서브넷을 하나씩 선택합니다.
2. 퍼블릭·프라이빗 서브넷 이름과 연결된 VPC를 확인하고 삭제합니다.
3. 확인 창에 `영구 삭제`를 입력해 실행합니다.
4. 서브넷을 사용하는 자원이 남아 있으면 먼저 정리한 뒤 각 서브넷의 삭제 결과를 확인합니다.

## 17. 사용자 라우팅 테이블과 VPC

1. 서브넷 정리 후 실습용 사용자 라우팅 테이블의 연결된 자원 수를 확인합니다.
2. 연결 수가 0개인 사용자 라우팅 테이블을 삭제합니다.
3. `vpc_1`과 `vpc_2`를 차례로 선택하고 `영구 삭제`를 입력해 삭제합니다.
4. 기본 라우팅 테이블과 인터넷 게이트웨이는 VPC 삭제 처리에 따라 정리됩니다.
5. 실습 VPC와 관련 라우팅 테이블이 남아 있지 않은지 확인합니다.

## 18. 키 페어

1. Beyond Compute Service > 키 페어로 이동합니다.
2. 서버 접속에 사용한 실습용 `keypair`를 선택해 삭제합니다.
3. 확인 창에서 이름을 확인하고 `영구 삭제`를 입력합니다.

## 19. 접근 키

1. 오른쪽 위 내 계정 > 자격 증명으로 이동합니다.
2. S3 액세스 키 목록에서 실습 프로젝트의 키를 선택해 삭제합니다.
3. IAM 액세스 키 목록에서 실습용 `test-key`를 선택해 삭제합니다.
4. 확인 창의 프로젝트와 키 이름을 확인하고 `영구 삭제`를 입력합니다.
5. 두 목록에서 실습용 키가 사라졌는지 확인합니다.

이것으로 실습 자원 정리를 마칩니다.
