# KakaoCloud 스크롤 소개 화면

`/`의 원래 화면 안에서 스크롤에 따라 연출이 이어지도록 구성했습니다. 첫 화면에는 기존 환영 문구·ConfigMap 그라데이션·왼쪽 위 원·Pod 이름·DB 버튼만 보입니다. 스크롤하면 두 원이 오른쪽으로 이동하고, 승인한 Flow 영상의 장면과 Kubernetes Engine 소개 문구로 이어집니다. 위로 스크롤하면 역방향으로 복원되어 원래 실습 화면으로 돌아옵니다. 영상은 로컬 이미지 시퀀스로 포함되어 있어 실행할 때 Flow 로그인이나 외부 영상 서비스 연결이 필요하지 않습니다.

## 실행

Java 17 이상이 필요합니다. 기존 Maven 빌드 방식을 그대로 사용합니다.

```sh
./mvnw spring-boot:run
```

Windows에서는 `mvnw.cmd spring-boot:run`을 사용합니다. 기본 주소는 `http://localhost:8080/`입니다.

이 작업 폴더에서는 Java 17을 준비해 두었습니다. PowerShell에서 `start-preview.ps1`을 실행하면 이 런타임을 찾아 `http://127.0.0.1:18780/`로 실행합니다. 서버를 종료하려면 실행한 창에서 Ctrl+C를 누르세요. 다른 컴퓨터로 소스를 옮긴 경우 Java 17 이상의 JAVA_HOME을 설정하세요.

## 화면 동작

- 첫 화면에 별도 안내·헤더·메뉴를 추가하지 않았습니다.
- 같은 화면이 잠시 고정된 상태에서 기존 원들이 움직이고, 실습 내용이 서서히 위로 이동하며 사라집니다. 웹에서 움직이는 두 원과 영상의 시작 구도를 맞춘 뒤, 짧은 겹침으로 실제 영상 프레임이 이어받습니다.
- 승인한 23.625초 무음 영상을 24fps, 1280×720의 AVIF 567장으로 변환했습니다. 원본의 해상도·프레임 수·타이밍은 유지하고 압축 형식을 최적화했습니다. 각 프레임이 스크롤 위치에 대응하므로 재생 버튼이나 영상 자동 재생 권한이 필요하지 않습니다. 원본 3장면의 연결 지점은 영상의 7.8초와 15.6초입니다.
- 영상은 화면 안에 전체가 들어오도록 표시합니다. 창 비율이 달라도 물체와 장면을 잘라내지 않으며, 남는 영역은 `#1a1a2e` 배경으로 채웁니다. 사이트용 마스터의 오른쪽 아래 Veo 표시는 주변 배경으로 정리했습니다.
- 관리형 제어 영역 → 다중 가용 영역 → VPC·클라우드 서비스 연동 문구가 각각 등장·유지·퇴장합니다. 모든 투명도와 위치는 스크롤 위치로 계산하므로 반대로 올려도 자연스럽게 복원됩니다.
- ‘실습으로 돌아가기’는 새 요청이나 주소 변경 없이 문서의 처음으로 이동합니다. 펼쳐 둔 DB 패널과 결과 DOM을 유지합니다.
- 긴 DB 결과로 실습 화면이 커진 경우 그 내용을 먼저 읽고 난 뒤 연출이 시작됩니다. 결과창 안의 스크롤은 소개 영역으로 이어지지 않습니다.
- 모바일, 높이 640px 이하의 창, 움직임 줄이기 설정에서는 기존 첫 화면 다음에 마지막 장면의 정지 이미지와 장점 설명을 배치합니다. 긴 빈 스크롤 구간은 만들지 않습니다.
- AVIF를 지원하지 않거나 첫 영상 이미지 요청에 실패하면 WebP 포스터를 사용하는 정적 소개로 전환합니다. JavaScript 비활성 상태에서도 포스터·소개 문구·실습 링크를 사용할 수 있습니다.
- `/experience`에는 독립 소개 화면을 유지하되, 루트와 같은 실제 영상·포스터를 공유합니다. 템플릿·스타일·스크립트는 별도로 유지하고, 중복된 임시 SVG 시퀀스와 생성 도구는 제거했습니다.

## 보존한 실습 기능

`HelloController.java`, `DatabaseApiController.java`, `DatabaseConfig.java`, `pom.xml`은 원본을 유지했습니다. `welcome.html`에는 스크롤 가능한 첫 화면 레이아웃과 소개 fragment를 추가했고, 기존 `.content` 안의 실습 요소와 DB 처리 JavaScript는 원본 그대로 유지했습니다. `/`, `/db1`, `/db2`의 주소와 동작도 그대로입니다. 소개 화면은 DB API를 호출하지 않습니다. 특히 `/db1`은 데이터 삽입 동작이 포함되어 있어 자동 호출이나 미리 불러오기를 추가하면 안 됩니다.

루트의 연출은 `.lab-story` 안에만 적용됩니다. 첫 화면은 원래 내용의 DOM과 기본 모양을 유지하고, 스크롤이 진행된 뒤에만 위치·투명도를 바꿉니다. 원래 원의 맥동 애니메이션은 안쪽 요소에 유지하고, 바깥 wrapper를 움직여 충돌을 피했습니다. ConfigMap 그라데이션은 원래 실습 화면의 높이 안에서 그립니다. 화면에서 완전히 사라진 버튼은 잠시 포커스 대상에서 제외하고, 돌아오면 복구합니다.

`/`에는 `immersive.css`와 `immersive.js`가 추가되지만, JavaScript를 사용하는 첫 화면에서는 실제 스크롤이 시작되기 전까지 영상 이미지 요청을 만들지 않습니다. 프레임용 일반 `src`나 preload/prefetch를 추가하지 않았습니다. 실제 DB 연결과 Pod 분산·HPA는 이 로컬 환경에 구성되어 있지 않으므로 해당 실습의 운영 환경 검증은 별도로 진행해야 합니다. HPA의 기존 `wget /` 요청은 JavaScript나 이미지를 실행하지 않으며, 늘어난 HTML 응답 크기의 영향은 실제 강의 환경에서 재확인하세요.

## 포함된 영상 자산과 교체 방법

두 소개 화면의 공유 자산은 `src/main/resources/static/experience/film/`에 있습니다.

- `frame-000.avif`부터 `frame-566.avif`: 승인된 사이트용 수정 영상의 모든 프레임을 AVIF CRF 20으로 인코딩했습니다. 현재 합계는 9,235,265바이트이며 `manifest.json`의 `frameBytes`에도 기록됩니다.
- `poster.webp`: 마지막 장면을 WebP 품질 82로 인코딩한 40,672바이트의 정지 이미지. 모바일·움직임 줄이기·AVIF 오류·JavaScript 비활성 상태에서 사용합니다.
- `manifest.json`: 프레임 수·크기·시간·원본 SHA-256·장면 연결 지점·변환 정보를 기록했습니다. 사이트용 마스터의 표시 정리 상태는 `attributionPreserved: false`, `visibleWatermarkRemoved: true`이며, 화면 영역을 자르지 않았으므로 `crop: false`입니다.

프레임·포스터·manifest를 포함한 현재 영상 자산 합계는 9,276,728바이트입니다. `ExperienceMediaConfig.java`는 Spring의 정적 자산 응답에 AVIF MIME 형식 `image/avif`를 등록합니다. 기존 컨트롤러·설정 파일을 바꾸지 않고 AVIF를 올바른 형식으로 제공합니다.

사용자가 승인한 `kakaocloud-flow-clean-preview.mp4`에서 오른쪽 아래 표시를 정리한 `kakaocloud-flow-site-master.mp4`를 사이트용 원본으로 사용합니다. ①·②의 불필요한 선을 정리했고, ③은 깨끗한 시작·끝 기준 이미지로 재구성한 수정본입니다. 이전 제작 원본은 별도 보관했습니다. MP4 자체는 웹 앱의 필수 실행 자산이 아니며 제작용 원본으로 별도 보관합니다.

새 영상으로 바꾸려면 왼쪽 문구 여백과 두 원의 시작 구도를 유지한 마스터 영상을 준비하고, Python 3과 `libaom-av1`·`libwebp` 인코딩을 지원하는 FFmpeg/FFprobe를 설치한 환경에서 다음을 실행합니다. 추가 Python 패키지는 필요하지 않습니다.

```sh
python tools/extract_scroll_film.py /path/to/kakaocloud-flow-site-master.mp4 --format avif --crf 20 --poster-quality 82 --visible-mark-cleaned
```

FFmpeg/FFprobe가 PATH에 없으면 `--ffmpeg`, `--ffprobe` 또는 `FFMPEG`, `FFPROBE` 환경 변수로 실행 파일을 지정할 수 있습니다. 도구는 프레임과 마지막 장면 포스터, manifest를 다시 생성하며 화면 영역을 자르지 않습니다. `--visible-mark-cleaned`는 이미 표시를 정리한 입력 영상의 상태를 manifest에 기록하는 옵션입니다. 이 옵션 자체가 영상을 보정하지는 않습니다. 표시를 유지한 새 영상에는 이 옵션을 생략하세요.

AVIF 전환은 임시 YUV 파일을 사용하므로 원본 영상 외에 작업용 디스크 공간도 필요합니다. 도구가 필요한 여유 공간을 확인하고, 새 프레임을 모두 인코딩·디코드 검증한 뒤 기존 자산을 교체합니다. 현재 원본의 임시 YUV 크기는 약 784MB이며 작업 후 제거됩니다.

이후 `templates/fragments/immersive-story.html`의 `data-frame-count`, `data-frame-width`, `data-frame-height`, `data-frame-pattern`과 `fragments/cloud-experience.html`의 공유 프레임 경로·개수를 결과에 맞춥니다. 패턴의 `{index}`는 0부터 시작하는 3자리 숫자입니다. 움직이는 화면의 `data-src`는 첫 AVIF 프레임, `data-static-src`와 noscript 이미지의 `src`는 WebP 정지 포스터를 가리킵니다. 첫 실습 화면의 지연 로딩을 유지하려면 활성 이미지에 일반 `src`나 preload를 추가하지 마세요. 해상도를 바꾸는 경우 `immersive.js`에서 사용하는 원의 연결 좌표도 새 기준에 맞춰야 합니다.

같은 파일 이름으로 자산을 교체한 경우 두 화면의 프레임 패턴과 모든 포스터 URL의 버전 쿼리도 함께 올립니다. 현재는 `?v=3`을 사용합니다. 이 값이 바뀌어야 이전에 방문한 브라우저도 교체 전 이미지 대신 새 프레임과 포스터를 요청합니다.

현재 스크롤 진행률 2–12%에서 웹의 원이 이동하고, 12–18%에서 영상으로 전환합니다. 18–94% 구간에 전체 영상이 대응합니다. 소개 문구의 등장·유지·퇴장은 `immersive.js`의 `intervals`, 원의 이동과 전환은 `pose`에서 조정합니다. 영상 길이나 장면 구성이 달라지면 이 구간도 함께 검토하세요.

루트의 화면 문구는 `fragments/immersive-story.html`, 스타일은 `immersive.css`에서 수정합니다. 독립 `/experience`는 `fragments/cloud-experience.html`, `experience.css`, `experience.js`를 사용하며 영상은 같은 `film/` 자산을 참조합니다. 서비스 문구의 근거는 [Kubernetes Engine 공식 개요](https://docs.kakaocloud.com/service/container-pack/k8se/k8se-overview)입니다. 영상은 장점의 추상적 표현이며 실제 클러스터 상태나 HPA 작동을 나타내지는 않습니다.

프레임 로더는 동시 요청 4개와 이미지 캐시 14개를 상한으로 사용합니다. 화면 밖이나 비활성 탭에서는 추가 프레임 요청을 멈춥니다. 전체 시퀀스 다운로드를 기다리는 로딩 화면은 없습니다.

최적화 전 공개 버전 `41902c990df3afb4e621bcffdd8d6a982add2311`의 비교 기준은 소스 15,788,269바이트, JAR 38,625,475바이트, WebP 영상 프레임 14,446,074바이트입니다. 최적화판은 프레임을 줄이거나 화면을 축소하지 않고 AVIF로 다시 인코딩해 영상 프레임 용량을 약 36.07% 줄였으며, 독립 소개 화면의 중복 임시 자산도 제거했습니다. 현재 자산의 정확한 바이트 수와 인코딩 설정은 manifest로 확인합니다. 브라우저의 전체 다운로드 용량과 스크립트의 이미지 캐시 개수는 서로 다른 값입니다.

최적화 후 소스는 약 9.5MB로 약 40% 줄었고, 실행 JAR는 33,188,915바이트로 약 14.08% 줄었습니다. 소스 크기는 문서도 포함하는 합계를 반올림했으며, Docker 이미지 크기는 직접 측정하지 않았습니다.

대표 프레임 7장의 주요 그래픽 영역을 같은 마스터와 비교한 평균 SSIM은 기존 WebP 0.990600, AVIF CRF 20 0.991264였습니다. 이 화질 비교 표본과 별도로, 전체 567장의 디코드·수량·크기를 검증했습니다.

## 검증 범위

- `AdvancedCourse/src/spring-code`에서 Java 17로 `mvnw.cmd -B -ntp clean verify`를 실행해 테스트 6개, 실패·오류 0개로 빌드에 성공했습니다. 기존 `src/spring`의 소스와 추적 중인 `target/`은 변경하지 않았습니다.
- Maven 자동 검증은 앱 시작, 소개 경로와 DB 호출 분리, 루트의 실제 환경 모델·실습·소개 공존, 첫 화면의 이미지 지연 로딩을 다룹니다.
- 두 소개 경로가 같은 프레임 수·패턴·정적 포스터를 사용하는지 확인합니다. 실제 렌더링된 경로의 처음·중간·마지막 AVIF와 WebP 포스터, manifest의 일치 여부 및 `Last-Modified`를 이용한 조건부 요청의 304 응답을 확인합니다. 이 요청들은 DB에 접근하지 않습니다.
- DB는 모의 객체로 대체하여 `/db1`의 INSERT 후 SELECT, `/db2`의 SELECT 전용 동작을 확인합니다. 검증 때문에 실제 DB에 데이터를 삽입하지 않습니다.
- AVIF 567장 전체의 디코드와 수량·크기를 확인했습니다.
- 기존 실습 콘텐츠와 인라인 DB 스크립트, DB 컨트롤러·설정·기본 컨트롤러·pom은 Git 원본과 동일함을 확인했습니다.

최적화판의 실제 로컬 미리보기에서 첫 화면의 실습 콘텐츠 위치·크기·배경이 적용 전과 동일하고, 처음에는 영상 이미지의 `src`가 지정되지 않음을 확인했습니다. AVIF의 실제 HTTP 응답 형식도 `image/avif`로 확인했습니다. 0–566 프레임의 빠른 정방향·역방향 스크롤과 원의 연결 위치, 세 장면의 문구 가독성, 열린 DB 패널을 유지한 실습 복귀를 확인했습니다. 390×844 모바일에서는 가로 넘침 없이 WebP 정적 소개로 전환됩니다.
